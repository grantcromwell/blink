My first attempt was with a ido sbc 2d06 but i couldn't find the stock firmware online from a reliable source so i went with the Rasberry pi 4 to handle keyboard inputs on the host machine. I flashed Debian 12 on a micro sd card and changed the boot configuration text to enable uart and I added dual role data condition for the usbc power port to enable serial communication over usbc insted of just power. After that I added a serial login service for debugging over usbc at 115200 baud, which later would cause some issues. The screen command wasnt initially working so i added two new modules, gSerial and DesignWare, which fixed the problem and allowed the Pi to run in peripheral mode with communication over usbc. The micro sd card that was used was a card I found lying around the house and when gadget mode began to work, it prompted me for a password, which I forget. Throughout the troubleshooting process, I wondered if I was just better off quitting and using a esp32 but I decided that I should just continue and maybe think of that next time. When I was reconfiguring a passwordless login in the root filesystem of the sd card, I thought about it even more. After some time spent debugging, the serial console worked without a password. I then began to work on the application to drive blinking LED on the pico over UART. I tried to use artificial intelligence to help generate boilerplate code for the bridge script that ran on the Rasberry pi but most of the time it would get confused on which hardware protocols I was intending to use or it would lie about pinouts. I ended up revising majority of the boilerplate but I kept the functions for the hash table. At first when I tried to use rshell to copy over the files to the pico it wasnt working, but then I realized there was a lingering screen process that was preventing me from copying the files over. After killing that process I was able to copy over the led script to the rasberry pico. My next issue was getting the bridge script to run indefinitely on the Rasberry pi. At first, the host to Rasberry Pi login service was interfering with communication from the Rasberri Pi to the Pico, but after changing the login service baud rate to 9600 and creating a background service to always run the bridge script even through restarts, I was able to get it working. This broke my ability to use the virtual serial port commands but by the time I realized this, the script already worked. Once the baud rate issue was corrected, the bride script ran on the rasberry pi and communication over uart to the pico was correctly blinking inputs in morse code. The LED then began flashing when the host script was ran and characters entered the program.

When I first switched to two Arduino nano esp32s, I was able to get uart communication between the two working on pins D0 and D1. The first esp32 would send a messege to the second to blink an LED, then it would send a messege for the second esp32 to interpret and turn off the LED. This part was worked well and the next step was displaying a 1 or a 0 when the first esp32 sends a command to turn the LED off or on for the second esp32 on a I2C display. At first, I thought my display was broken. It wouldn't print an I2C memory address and so I thought the part was faultly. To verify, I used a multimeter to test and see if the pins on the esp32 for its 3.3V pin were emmiting voltage. To my suprise it was, so next I tested if the VCC pin on the display was emmiting voltage and it wasnt. For a while, I couldnt figure out what was the problem, but then I realized the display most likely needed 5V to power on insted of 3V. To solve this issue, I used a rasberry pi pico which emits 5V on its VBUS insted of 3.3V.  The next problem I had was incorrectly wiring the pins on the pico. I was using the wrong pins but my code was correct, after addressing this issue I was able to display a circle from source code I recieved online. The next step of the process was displaying a 1 when the LED was on and a 0 when the LED was off.
